# AdoptLab 产品基线 PRD · v0.3

核验日期：2026-10-02。[English](product-prd.md)。

## 定位与用户任务

AdoptLab 面向小型 MCP 工具维护团队，提供接入验证与材料修订工作台。维护者通过任务契约、实际工具执行、独立验收、失败证据和修订复验，决定具体修改及其接受条件。开发者完成首次任务，理解结果并提交可处理的阻力反馈。

首要用户为 MCP 维护者、开发者文档负责人和接入工具的开发者。提供 MCP 的 AI API 团队属于潜在用户；通用 API 接入、多人协作和托管执行留作扩展。用户准备时间、付费意愿与采用收益仍需外部观察支持。

## 问题依据与版本目标

v0.2 的 48 次协议执行及 144 次模型实验支持工程机制与探索性材料对照。当前页面和配置可直接复查三项阻力：开发者同时面对维护者配置；Quick Start 默认选择十二任务、两材料；环境结果采用原始 JSON。

v0.3 目标：用户安装后，沿清晰路径完成一个任务，再向维护者交付关联证据的反馈。完整实验、外部接入和修订管理继续保留。

## 完整流程与优先级

| 环节 | 需求与取舍 | 验收 |
|---|---|---|
| 环境准备，P0 | 独立 Python 环境与可写运行目录；按内置、Filesystem、模型目标检查 | 内置任务可在缺少 Docker、密钥和云追踪时执行 |
| 首次任务，P0 | task-01、材料 B、一次协议执行；复用已有执行器 | 单次运行、零模型请求、独立验收通过 |
| 解释结果，P0 | 展示状态、工具调用、费用、失败证据和处理动作 | 错误输出可被复验识别；取消、超时保留状态 |
| 反馈交接，P0 | 自动关联运行、任务和材料；明确维护者入口 | 打开入口后恢复对应运行与反馈 |
| 材料修订，P0 | 保存不可变版本、父版本和理由；同条件复验 | 材料变化、条件可比、终态成功、独立验收通过 |
| 中断恢复，P1 | 核验 Windows 进程退出状态 | 已退出进程可登记中断；未知费用继续预留 |
| 采用研究，P1 | 使用统一观察台账和来源字段 | 每条记录关联证据、问题、修订和复查 |

材料 B 为首次协议任务提供明确指南；协议工作流按参考步骤执行。指南与工具描述对模型行为的影响，通过真实模型对照测量。首次入口的一次执行与原配置的二十四次执行属于配置范围变化，人工接入时间改善需实际观察。

## 竞品与产品判断

[竞品实测](competitive.md)覆盖 Promptfoo 原生 MCP、模型工具接入、Langfuse SDK／云端观察以及手工脚本与表格。统一比较首次任务、失败检查与修订交接，记录版本、费用、步骤、限制及未完成体验。

已有评测工具提供广泛配置和生态，Langfuse 提供共享实验与追踪。AdoptLab 聚焦任务验收、材料版本和反馈复验的连续流程，承担较窄接入范围、本地运行与有限协作能力的取舍。是否保留独立产品，依据维护者采用成本和需求观察决定。

## 指标与后续决策

任务成功由后端终态与独立验收确认。交接质量按“原运行—反馈—新材料—复验”是否齐全衡量。首次价值时间需记录参与者起点、终点与协助；自动运行耗时仅描述执行过程。来源、重复事件和撤回处理沿用现有机制。

公开站点继续浏览保存证据，本地承担真实执行。工程检查与角色评审使用同一问题台账、分别保留来源字段；可核验的外部参与人数与人次目前为零。后续邀请、知情说明和观察协议见私有执行包。
